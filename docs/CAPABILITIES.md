# Capability boundaries

This package combines creative guidance with small deterministic tools. Your existing assistant supplies reasoning and, when available, perception and other production tools. Availability is not the same as a successful end-to-end production run.

| Capability | Distributed here | Evidence / remaining work |
| --- | --- | --- |
| Route selection and basic development | `video-creation` and its three self-contained route references | Worked text cases and task evaluations; not a guaranteed audience response |
| Source registration and long-text continuation | Standard-library project tool with immutable input copies, hashes, chunks and artifact records | Mechanical tests; no automatic entity resolution or story extraction |
| Local video observation | CPU overview, time windows, crops and observer journal | Synthetic-media tests and three maintainer source-window trials; static-sequence reasoning leaves real-time rhythm/audio unverified |
| Local dialogue observation | Optional CPU ASR, source-clock subtitle/WhisperX import, linked audio/image windows | Machine words and anonymous voice labels remain candidates; role attribution needs actual source evidence, and listening is not automatically established |
| Performance and highlights | Event cards, attention handoff, protected details and review | Fictional text examples; no expression-transfer or generator-control engine |
| Advanced novel analysis | Basic workflow is self-contained; optional specialist skills may augment it | Full-book semantic consistency and a complete long series have not been established by this package |
| Image generation and stable character assets | Handoff methods only | Requires the host's image tools and real identity/style asset checks |
| Video generation | Backend-neutral handoff only | Requires a real backend; this package does not submit or recover model jobs |
| Dialogue, narration and subtitles | Script/voice/timing requirements and handoff | Requires actual voice/audio/editing tools; recurring voices, literal lines and lip sync need a dedicated sample |
| Editing and final review | Shot duties, intervals and review methods | Requires an editor/renderer; writing an edit plan does not create a finished film |
| Publishing and commercialization | Publication-readiness questions, when requested | No account integration, automatic posting, platform approval or revenue guarantee |

## Maintainer's local production context

The originating workspace has existing ComfyUI/H3 generation and assembly tools, with actual no-dialogue short-video production and selected reference tests. This establishes useful local building blocks; it is not evidence that this public package can automatically render a complete novel adaptation.

Important adapter distinctions:

- Backend mode names are not universal. An image/audio-reference mode called `r2v` in one client is not automatically a motion-video reference. Confirm actual input wires.
- A backend's default prompt may impose live-action styling. For a comic or animation project, pass and verify an explicit visual-form prompt rather than relying on that fallback.
- Historical benchmark budgets, output roots and candidate IDs belong to their original projects. New projects require their own receipts and resource limits.
- Native audio availability does not prove a stable recurring voice, exact Chinese dialogue or correct lip sync.
- Subtitle rendering, voice synthesis and transcript alignment are separate capabilities. A subtitle renderer cannot create the missing voice or correct timings.

## Novel production readiness

Text development can begin with an accessible source and adaptation brief. Media production additionally needs an agreed visual form, recurring identity assets, a dialogue/narration strategy and a tested backend profile.

For a new spoken series, a useful first validation is a short line, a second shot with the same speaker, and a listener's reaction. Check actual words, voice identity, synchronization, expression and inter-shot state. Decide between native dialogue, external voice or narrated limited motion from that result, then test a small episode batch before scaling.

These are production checks for the chosen project, not a requirement to ask the user for approval on every shot. Preserve existing authorization and continue useful work; mark capability gaps explicitly.
