# One hub, three creation routes

Use `video-creation` as the entry point. It selects the smallest relevant route and carries the source evidence, story choices and production state forward. The focused `video-observation` and `performance-direction` skills remain available independently.

| Starting material | Route | First useful result |
| --- | --- | --- |
| A video URL or local clip; same-story reconstruction or role replacement | `reference` | Actual source-access status, observed action chain, protected highlights and reconstruction brief |
| A novel or serialized prose | `novel` | Traceable source analysis, adaptation choices, dramatic units and an episode map |
| An idea, or a popular video's mechanism as inspiration | `original` | Distinct mechanisms, a reasoned choice, story and playable highlights |

The route is a creative distinction, not a file extension. If the user wants the same story with new actors, preserve it. If they want a new story inspired by a reference, identify what changes in the goal, strategy, choice and consequence. Do not call a prop substitution a new mechanism.

## Reference reconstruction

1. Obtain actual accessible media through the host's connector, browser or supported downloader. A URL, post caption or transcript is not pixel evidence. The bundled tools do not download URLs.
2. Inspect shots and revisit uncertain interactions using available image/video observation tools. Keep source versions and actual viewed ranges.
3. Record the visible causal sequence, approximate attention, body actions, partner responses and information order. Separate interpretation and uncertainty.
4. Protect the reference's meaningful beats while applying the user's permitted role, location or style changes. Pass those requirements into shots and actual candidate review.

A link-only project can still record the source and prepare the identity/change brief. It cannot truthfully produce an observed action analysis until the media or equivalent inspectable evidence is available.

The helper can retain a URL-only dependency for an analysis/development access brief, labeled as metadata evidence. Script and later source dependencies require real local files. A valid brief file is not evidence that the clip was watched.

## Novel to episodic comic drama

1. Preserve the original input and register its hash. For the built-in text tool, provide UTF-8 TXT/Markdown. Convert DOCX, EPUB or scanned PDF with an available reader first, retaining original and converted versions separately.
2. Read manageable source chunks; extract factual events, character/alias candidates, world rules, audience rewards, setups and unresolved references with locators. Tool-delivered chunks are not automatically analyzed chapters.
3. Aggregate dramatic units; decide what to keep, compress, combine, move earlier or add. Chapters do not prescribe episode boundaries. Preserve who knows what at each point.
4. Develop the story engine, episode entries/results/exits, scripts, recurring assets and shot duties. Carry the compact series ledger into each continuation.
5. Before scaling production, test the chosen visual form and sound mode. Narrated limited motion, dialogue animation and cinematic scenes have different production needs.

“Hongguo-oriented” describes the user's target audience and distribution intent. It does not establish a fixed episode count, duration, paid cliffhanger pattern or current platform acceptance. Verify actual publishing requirements separately when publication is requested.

## Original or trend-inspired story

Begin with a character's goal and habitual tactic, the obstacle that pressures it, the choice and visible consequence. When ideating, compare a few genuinely different mechanisms, then develop the best-supported direction. A selected idea or local repair does not need a new comparison exercise.

If a reference is involved, distinguish observable features from your inferred mechanism, then write what the new story changes. A claim that something is currently popular needs dated sources or observed metrics. Without them, label it a reference rather than a verified trend.

Test appeal before elaborate coverage: what does the viewer want to see next, what choice creates the turn, what visible behavior carries it, and how does the result answer the setup? Humor, suspense, recognition and process satisfaction need different designs.

## Shared handoff and resume

All routes share a compact brief, source/coverage records, relevant canon and continuity, and event-to-shot requirements. Use the bundled `project_tool.py` for file identity, text chunks, delivered-read bookkeeping, artifact hashes and the next step. It neither writes stories nor approves production quality.

The production handoff identifies the actual backend/profile, identity/style/action/voice reference roles, literal dialogue when present, generated candidates, adopted intervals and separate technical/action/continuity/highlight/rhythm findings. These are side records until an adapter actually maps them into a backend. See [capability boundaries](CAPABILITIES.md).
