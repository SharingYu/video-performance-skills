# Series Ledger

Use for a serial or long-source adaptation when continuity needs durable memory. Keep entries concise and source-linked. Read only the relevant state for the current unit; an unread section stays unread, and a proposed rewrite stays separate from source canon.

## People, names and knowledge

| Character ID | Source names / titles | Supported identity links or provisional alias candidates | Goal / relationship state | What this character knows at the current point | Source location or explicit adaptation choice |
|---|---|---|---|---|---|

Do not merge two names merely because they resemble each other. Record the evidence for a confirmed link. Keep narrator/reader knowledge separate from what a character can act on.

## World, objects and physical state

| Item or rule ID | Established condition / limitation | Holder, location or current physical state | Change and its cause | Source location / episode |
|---|---|---|---|---|

An ability needs the conditions and costs the source establishes. A prop or injury cannot reset across episodes without a reason. Separate user-approved redesign from a source fact.

## Setups, promises and consequences

| Promise / setup ID | What the audience expects | Established at | Required condition for payoff | Current status / actual consequence | Open question or unread material |
|---|---|---|---|---|---|

Do not mark a payoff complete because it was planned. A newly revealed fact, a reversal of strategy, an emotional reward and a next-episode question can have different responsibilities.

## Episode handoff

| Episode ID / version | Entering state and knowledge | Pursuit / pressure | Consequential choice and local result | Information released | Exiting state inherited next | Evidence / adaptation links |
|---|---|---|---|---|---|---|

Make neighboring entries connect. Avoid filling a whole season with confident episode facts while the source is only partly read.

## Adaptation changes and open work

| Change ID | Source units / locators | Add / remove / merge / move / redesign | Function preserved or intentionally changed | Affected episodes / assets | Decision and remaining question |
|---|---|---|---|---|---|

If source content changes, retain the former version and locate affected entries. A current file hash or populated ledger is bookkeeping evidence; story consistency still needs review against the actual source and current script.
